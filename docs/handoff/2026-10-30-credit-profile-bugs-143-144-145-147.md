# Free plan welcome bell; credit profile parse, SSN mask, single notification (BUG-143, 144, 145, 147)

**Date:** 2026-10-30
**Branch:** bugfix/all-bugfix
**Author:** Awlad

## Problem
- **BUG-143:** a client created on the Limited Free Plan with no end date (every embed form conversion, or Add Client with no date) got the bell "Your free trial has started - Your free trial is active until N/A." `BorrowerService::store()` always sent `borrower.account.trial_started` with `date => 'N/A'`.
- **BUG-144:** `POST common/borrowers/parse-credit-profile`:
  - accepted any readable PDF; a non-report came back "parsed successfully" with every field empty, and its PDF and `borrower_documents` row were kept;
  - a broken PDF returned the raw parser error ("An error occurred while parsing the credit report: Unable to find startxref").
  - The profile being saved without Save was the admin frontend's auto-save, fixed there.
- **BUG-145:** `GET common/borrowers/get-credit-profile/{id}` returned the report's SSN (`personal_info.ssn`) as all 9 digits.
- **BUG-147:** two "credit profile updated" bells for one report. The API sends it only on save. The admin frontend saved on upload too (auto-save), and that's fixed in Fch-admin-frontend-react.

## Solution
- **BUG-143:**
  - New notification type `borrower.account.free_plan_started`: "Your Limited Free Plan is active", with no date.
  - `BorrowerService::store()` sends it when there's no end date. With an end date it still sends `trial_started` with the real date, never 'N/A'.
  - The email (`BorrowerTrialMail`) already handled a missing date.
- **BUG-144:**
  - Parse refuses, with 422 and a plain message, both a PDF the parser can't open (`borrower.credit_profile_unreadable_pdf`) and one it finds nothing in (`borrower.credit_profile_not_a_report`).
  - "Nothing" means `looksLikeCreditReport()` finds no score, account, inquiry, address, name, SSN or DOB.
  - The check runs before the PDF is stored, so a refused file leaves nothing behind.
- **BUG-145:**
  - `FCH\Borrower\BorrowerCreditProfileResource` masks `personal_info.ssn` with `Ssn::mask()` (`***-**-6789`).
  - `saveCreditProfile` keeps the SSN on file when the mask is sent back.
  - `POST common/borrowers/{id}/reveal` accepts `field: credit_profile_ssn`. That's the report's SSN, logged as "Credit Profile SSN Viewed".

## Files changed

- `app/Http/Controllers/Api/V1/FCH/Common/Borrower/BorrowerController.php`: unreadable / not-a-report refusals in `parseCreditProfile()`, new `looksLikeCreditReport()`, keeps the stored SSN when a mask is saved.

- `lang/en/borrower.php`: `credit_profile_not_a_report`, `credit_profile_unreadable_pdf`.
