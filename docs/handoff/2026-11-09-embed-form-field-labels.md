# Embed form: every field named for screen readers

**Date:** 2026-11-09
**Branch:** bugfix/iframe-application-website
**Author:** Awlad Hossain

## Problem
SCRUM-435 S435-BUG-04: the embedded form's labels were not tied to their fields (brief section 5, AC 9). QA checked step 1 only, but 67 of the form's 75 labels had no `for`, across all 8 steps and the co-borrower card.

The report says a screen reader announces an unnamed box. More exactly, a field with a placeholder falls back to it, so "Business Email" would be read as "accounts@acme.com". Fields with no placeholder, such as the file uploads, had no name at all.

## Solution
Awlad chose to fix all 8 steps rather than step 1 only. There is no visual change.

- **Plain fields:** 46 labels now have `for`. The pairings were generated by a one-off script and checked in its printed list.
- **Co-borrower card:** 16 fields gained ids keyed by the card's index (`co_${index}_first_name`), so a second card does not repeat them.
- **Business Phone and Requested Amount:** a dropdown comes first in both input groups, and the label now points at the box being typed in. The phone's country dropdown gets a `visually-hidden` label; the currency already had an `aria-label`.
- **Document uploads:** each file input has an id and is named by its document type.
- **Yes/No questions (10 groups):** `role="radiogroup"`, `aria-labelledby` pointing at the question, and `aria-required`.
- **select2:** `nameSelect2()` adds the label to the drawn box's name and keeps the current choice in it. It also names a multi-select's typing area and a dropdown's search box.
- **Date pickers:** flatpickr's visible box is a copy with no id. `nameDatePicker()` gives it one and moves the label to it, so clicking the label opens the calendar.

**Behaviour a person will notice:** clicking a label now focuses its field, opens the calendar, or opens the file picker for a document type.

## Tests
- Added: `EmbedFormFieldLabelsTest`, 9 tests, reading the rendered markup. Seven of the first 8 failed before the change; `no_two_fields_share_an_id` already passed. The document-upload test was added alongside the fix and was not run before it.
- Added: `apply-form-accessibility.spec.ts`, Chromium, against the local API. It runs axe's naming rules on each step and on a co-borrower card. It also checks the accessible names directly, clicking a label, and that a required select2 field still reports its error.
- **axe alone is not enough here:** steps 1, 2 and 3 passed axe before the fix, because axe accepts a placeholder as a name. The role-and-name checks and the PHP tests are what catch this defect.
- Suites run: `tests/Feature/EmbedForm`, 231 passed; website Playwright, 19 passed (including the 5 tracking specs); website Vitest, 18 passed; website typecheck clean. The whole API suite was not run.
