# SCRUM-434 QA bugs: lender matching, inactive lenders, fixed lender, embed Draft edit, commission split

**Date:** 2026-11-04
**Branch:** bugfix/embed-form-application-edit (backend and admin frontend)
**Author:** arafat-invento

## Problem
The SCRUM-434 feature test (04-Nov) logged four host-side bugs, plus a commission modal issue:

- **S434-BUG-01** – "Line of Credit", "SBA Loan" and "Refinance / Debt Consolidation" (loan application funding types) matched no lenders. Matching compared names exactly, and the lender categories are worded differently ("Business Line of Credit", "SBA Financing", "Debt Consolidation / Refinance").
- **S434-BUG-02** – an Inactive lender was listed in Lender Information and could be assigned on both pages.
- **S434-BUG-03** – the funding request page still changed the lender of an application past the 11 editable statuses (open item O76).
- **S434-BUG-04** – a step save on an embed-form Draft moved it to On Hold. The edit pop-up also said the Draft was "signed and submitted" and would need re-signing.
- **Commission modal** – admin/partner rates could be edited without a success fee, and could end up not adding to 100% (e.g. admin blank, partner 91%).

## Solution
- **BUG-01**: `LenderMatchService` loads `lender_product_categories` and matches a funding type to a category with the same meaningful words (case, word order, punctuation and filler words such as business/loan/financing are ignored). Nothing is hard-coded, so new categories work without code changes.
- **BUG-02**: only `Active` lenders are matched. Both assign endpoints validate `Lender::assignableRule()` (Active, not deleted) and return 422 `lender_not_active`.
- **BUG-03**: `FundingRequest::canAssignLender()` applies the linked application's rule. `funding-request/assign-lender` returns 422 `lender_locked`, the request details send `can_assign_lender`, and the admin request page shows only the fixed lender.
- **BUG-04**: a step save no longer moves a Draft back to On Hold. `edit_needs_confirmation` is now true only when an edit costs the signature or a re-sign is already owed, so an embed-form Draft opens without the "submitted" warning.
- **Commission**: the API requires admin + partner = 100 whenever `partner_commission` is sent. In the admin modal, the rates stay locked until a success fee is entered and go back to the default split when it is cleared. Changing or clearing one rate sets the other to the rest of 100.

## Follow-up 2026-11-05: funding types are the lender product categories
**Problem:** Preferred / Additional Funding Types were a hard-coded list (backend config plus a copy in each portal) worded differently from Lenders > Product Categories. That mismatch is why BUG-01 happened.

**Solution:** one list - exactly the Active lender product categories in their sort order, nothing else.
- Backend: `LenderProductCategory::fundingTypeNames()`, `GET /api/v1/common/funding-types` (`Global/General/LenderProductCategoryController` → `Services/Global/General/LenderProductCategoryService`, any signed-in user), embed form page (`EmbedFormPageController`) uses the same list. New rule `App\Rules\KnownFundingType` (Active category only) on `preferred_funding_type` and `additional_funding_types.*` in the borrower, partner and embed requests. The config list (`options.funding_types`) is removed.
- Admin + borrower portals: `fundingTypeOptionsFrom()` (exactly the categories) and `onlyFundingTypesIn()` in `data/profile.ts`, `useFundingTypes()` query. The Funding Request step offers only the categories and clears a saved type that is not one (old name, inactive category, funding sequence name), so it is chosen again. The hard-coded `fundingTypeOptions` list is gone.
- Database rows are not rewritten; an old name still matches lenders by words (F177) until it is re-chosen.

**Tests:** `Feature/General/FundingTypeOptionsTest`, `Integration/Funding/KnownFundingTypeTest`, `Unit/EmbeddedForm/SubmitEmbedFormRequestTest` (funding type checks moved to Integration); 7 FundApplication feature tests create the categories via `Tests\Support\CreatesFundingTypes` and send category names; admin and borrower `tests/data/profile.test.ts` and `FundingRequestStep.test.tsx`.
