### Before deploying this branch

1. **Run `php artisan migrate`.** It runs the backfills for F90 (play rows), F102 (encrypt SSNs) and F107 (application partner), and drops the unique index on product category names (F114).
2. **Check for users with no partner (F105).** Every user the query below returns is locked out after deploy. Give each one a partner, or remove it:
   `SELECT id, email, user_type FROM users WHERE deleted_at IS NULL AND (partner_id IS NULL OR partner_id NOT IN (SELECT id FROM partners WHERE deleted_at IS NULL));`
3. **reCAPTCHA keys (F112, F119).** Rotate the leaked key pair in the Google console first (O57). Then put the new site key and secret in CMS → Site Settings - the only source now. Delete `RECAPTCHA_SITE_KEY`, `RECAPTCHA_SECRET_KEY` and `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` from the server env files. With both keys set the contact form is checked; with neither, there is no reCAPTCHA.
4. **Check the domain env values (F122, F123).** `BASE_WEBSITE`, `BASE_API_URL`, `BASE_PARTNER_PORTAL` and `BASE_BORROWER_PORTAL` must be that environment's real domains - they always get a certificate go-ahead. A partner custom domain now needs Active Custom URL on to get one (run the query in the F123 handoff to find any that are off).
5. **Set `INTERNAL_RESOLVER_KEY` (F101)** in every environment and on the edge proxy. Without it, every domain lookup is refused.
6. **Set `CRON_ERROR_NOTIFY_EMAILS` (F97)** wherever scheduler alerts should go.
7. **Deploy fch-api, react-fch and borrower-fch together (F108, F110, F118, F120).** An older partner portal build still calls the removed single lead delete, and the Remove buttons need the new endpoints.
8. **Run `composer dump-autoload` (F106, F115–F118).** Several classes were deleted.
9. **Pass `--force` for production restores (F104).** Update any runbook that does them.
10. **Refunds given in the Stripe dashboard (F117).** There is no webhook, so mirror any such refund in the app by hand.
